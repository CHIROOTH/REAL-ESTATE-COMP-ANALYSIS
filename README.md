# Real Estate Comp Analysis

An AI-assisted residential comp engine built for the **KV Capital AI Engineer Hackathon**. The system automates the comp analysis workflow that currently bottlenecks home-builder loan underwriting at KV Capital: given a subject property, it finds the most relevant comparable sales, estimates value, and generates a bank-style AI underwriting narrative — all in one pipeline.

> **Hackathon context:** KV Capital finances home builders in Alberta. To back each loan, they underwrite what the home is worth — and the bottleneck is comp analysis: finding comparable recent property sales and using them to estimate value. This pipeline automates that process end-to-end.

## The Demo

> *"Here's the subject property → here are the selected comps → here's the valuation → here's the AI-generated underwriting rationale."*

**Input:**
```json
{
  "city": "Edmonton",
  "property_type": "Detached",
  "bedrooms": 4,
  "bathrooms": 3,
  "square_footage": 2100,
  "garage": true,
  "waterfront": false
}
```

**Output:**
- Estimated value range (e.g. `$612k–$640k`)
- Confidence score
- Top 5 comparable properties with distance/feature scores
- AI underwriting narrative:

> *"The subject property is most comparable to recent detached home sales in southwest Edmonton with similar square footage and finished basements. Properties with garages and updated roofing showed a 4–7% premium relative to otherwise similar listings."*

## Features

- **Hybrid similarity retrieval** — combines Haversine geographic distance with scaled Euclidean feature distance (configurable weighting, default 40% location / 60% features)
- **Four regression models** — Linear Regression, Ridge Regression, Random Forest, and XGBoost, each trained locally on a property's K nearest comps
- **Global XGBoost benchmark** — trained across the full dataset with early stopping for comparison
- **AI-generated appraisal reports** — uses a local Ollama LLM (Mistral by default) to write a structured underwriting narrative, then renders it as a formatted PDF via ReportLab
- **Automated data cleaning** — deduplication and missing-value removal
- **JSON output** — similarity results and valuation predictions saved for downstream use
- **Diagnostic figures** — scatter plots, feature importance charts, and model comparison bar charts

## Getting Started

### Prerequisites

- Python 3.8+
- [Ollama](https://ollama.com/download) (for the AI report step)

### Installation

```bash
git clone https://github.com/CHIROOTH/REAL-ESTATE-COMP-ANALYSIS.git
cd REAL-ESTATE-COMP-ANALYSIS
pip install pandas numpy scikit-learn xgboost matplotlib reportlab
```

### Ollama Setup (Step 4)

`explanation.py` calls a locally running Ollama server to generate the underwriting narrative. Set it up once before running the pipeline:

```bash
# 1. Download Ollama from https://ollama.com/download

# 2. Pull the model (Mistral is the default)
ollama pull mistral

# 3. Start the server
ollama serve
```

To use a different model, change `OLLAMA_MODEL` at the top of `explanation.py` (e.g. `"qwen2.5"`, `"llama3"`).

### Data

Place your raw data file at `data/canada_housing_data.csv`. The file should include columns such as `City`, `Province`, `Latitude`, `Longitude`, `Price`, `Bedrooms`, `Bathrooms`, `Acreage`, `Square Footage`, `Property Type`, `Garage`, `Parking`, `Fireplace`, `Waterfront`, `Sewer`, `Pool`, `Garden`, and `Balcony`.

### Running the Pipeline

Run the first three stages end-to-end:

```bash
python make.py
```

Then run the report generation step separately (requires Ollama running):

```bash
python explanation.py
```

> **Note:** `explanation.py` is currently configured with a hardcoded example property (`query_index: 77`). Edit the `input_data` dict at the bottom of the file to point it at a different result from `valuation_results.json`.

## How It Works

### 1. Preprocessing
Removes 4,082 duplicate rows. Drops columns that are too sparse to be useful (`Basement`, `Exterior`, `Heating`, `Flooring`, `Roof`). Removes any remaining rows with missing values, leaving ~40,814 clean listings.

### 2. Similarity Retrieval (Hybrid KNN)
For each property, `PropertySimilarityRetriever` computes a weighted composite distance:

- **Location distance (40%)** — Haversine great-circle distance (km) between properties
- **Feature distance (60%)** — Euclidean distance over StandardScaler-normalized features: bedrooms, bathrooms, acreage, sq ft, garage, parking, fireplace, waterfront, pool, garden, balcony, property type (one-hot), and sewer type (one-hot)

Both distances are min-max normalized to [0, 1] and combined as a weighted sum. The K nearest properties are saved per listing in `data/similarity_results.json`.

### 3. Valuation (Regression)
- **Global XGBoost** — trained on flattened features of every (query, K-neighbors) tuple across the full dataset (80/10/10 train/val/test split), validated with early stopping. KNN distance scores are included as features, giving the model explicit signal about how locally grounded each prediction is.
- **Local models** — for each query property, Linear Regression, Ridge, Random Forest, and XGBoost are each fit directly on its K nearest comps and used to predict the query price.

Output metrics include MAE, RMSE, R², and MAPE across validation and test splits. Results written to `data/valuation_results.json`.

### 4. AI Underwriting Report
`explanation.py` takes the valuation output for a given property and:
1. Computes influence weights for each comparable based on inverse total distance
2. Sends the full context to a local Ollama LLM, which returns structured JSON covering: estimated value, confidence rating, comp analysis, valuation rationale, price drivers (positive and negative), model selection rationale, and a final underwriting takeaway
3. Renders the JSON into a formatted PDF appraisal report (saved to `results/appraisal_report.pdf`) with sections for executive summary, comparable sales table, price drivers, model outputs, and confidence breakdown

## Configuration

| File | Constant | Default | Description |

## What I'd Build Next

The current pipeline is a strong foundation, but several improvements would make it production-ready for KV Capital's underwriting workflow:

- **Time decay** — weight recent comparable sales more heavily; stale listings should either be discounted or excluded
- **Outlier comp rejection** — automatically flag and remove comps that are statistical outliers before they skew the regression
- **Dynamic weight tuning** — learn optimal `W_LOC` / `W_FEAT` weights per property type or neighborhood rather than using fixed globals
- **Commercial property support** — extend the same KNN + regression + LLM pipeline to commercial borrowers
- **Richer features** — year built, renovation history, and architectural details are high-signal features that are currently missing from the dataset. Collect better data of more recent sale and listings along with domain expertise checking the results of the model to validate it.
- **Live MLS data** — replace the static CSV with a live data feed so comps reflect current market conditions
